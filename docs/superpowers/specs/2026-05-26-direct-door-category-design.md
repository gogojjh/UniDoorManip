# Direct Door Category — Design Spec

> **For agentic workers:** This document defines WHAT to build. The implementation plan (generated by writing-plans skill) defines HOW to build it.

**Goal:** Add "direct" door categories where the handle is always in the unlocked position, allowing the robot to pull/push the door directly without rotating the handle first. Covers LeverDoor, RoundDoor, Cabinet, Fridge, Window, Safe.

**Tech Stack:** Python 3.8+, Isaac Gym, PyTorch, NumPy, Zarr

---

## Motivation

Existing door categories (e.g., `LeverDoor_ccw_pull`, `RoundDoor_cw_push`) require a two-phase manipulation: (1) rotate handle to unlock, (2) pull/push door to open. The new "direct" categories represent doors whose handles are already unlocked, requiring only the pull/push phase.

## Design Principle

**Asset-driven behavior.** The URDF defines the door physics. Setting `joint_2` (handle joint) limits to `[0, 0]` makes the handle physically immovable. Downstream code reacts to this naturally via existing `open_door_flag`/`open_door_stage` checks (both evaluate `0 >= 0.75*0 = True`). The DP3 expert generator additionally detects "direct" task names and explicitly skips the handle-rotation phase.

**DOF index assumption:** In all existing URDFs, `joint_1` is the hinge (DOF 0) and `joint_2` is the handle (DOF 1). Some assets have a decorative `joint_3` of type `fixed` which consumes no DOF slot. The asset generation script must verify this invariant before modifying each URDF.

## Component 1: Asset Generation (UniDoorManip)

### URDF Modification

For each asset in a "direct" category:
- Locate `joint_2` in `mobility.urdf`
- Set `<limit lower="0" upper="0"/>`
- All other attributes (origin, axis, robot_name, mesh paths) remain unchanged

### Asset Copy

Copy these files from source to target directory:
- `mobility.urdf` (then modify joint_2 limits)
- `bounding_box.json`
- `handle_bounding.json`
- `texture_dae/` (entire directory)
- DO NOT copy `kinematics.json` (it is regenerated on demand via `extract_door_kinematics.py` and not present in all source assets)

### train_test_split.json

Each source category has a `train_test_split.json` at the category root (e.g., `LeverDoor_ccw_pull/train_test_split.json`). Copy this file verbatim from source category to target category. The train/test asset split is identical since the assets are the same doors with modified handle physics.

### Generation Script

A one-time Python script (`/tmp/generate_direct_assets.py`) receives a source→target mapping (8 pairs). For each pair:
1. Copy `train_test_split.json` from source category root to target category root
2. For each asset subdirectory in source:
   - `shutil.copytree` into target
   - Parse `mobility.urdf` as XML
   - Find `<joint name="joint_2">` → verify it exists and type is `revolute` (raise error if not found or wrong type)
   - Set `<limit lower="0" upper="0"/>`
   - Write back

This script is run once and not committed.

**Stage 2 skip logic** — at the top of the `mask2 = (self.stage == 2)` block in `get_action()`, set `open_door_flag` to True for direct tasks BEFORE any existing branch logic runs. The flag uses `|=` semantics so once set it stays True for the remainder of the episode. This causes all downstream branches to use `pull_action` instead of `rotate_action`.

The precise insertion point is: **after** `open_dir = quat_axis(handle_q, axis=2)` and **before** `handle_progress, is_lift = self._compute_handle_progress(mask2)`. Add:

```python
if self.task_name in self._DIRECT_TASKS:
    isaac.open_door_flag[mask2] = True
```

This is a single set (not `|=`) because it happens every frame for direct tasks, keeping the flag permanently True.

## Data Flow Summary

```
URDF: joint_2 [0,0]
    │
    ├──► base_env._perform_actions: open_door_flag=True, open_door_stage=True
    │       → handle torque skipped, door feedback applied
    │
    └──► gen_demo.get_action():
            if task in _DIRECT_TASKS:
                open_door_flag = True (explicit, sticks via |=)
            → all branch logic uses pull_action path (not rotate_action)
```

## Verification

1. **Asset integrity**: Each direct asset directory has `mobility.urdf` with `joint_2` having `<limit lower="0" upper="0"/>`, plus `bounding_box.json`, `handle_bounding.json`, `texture_dae/`
2. **train_test_split.json**: Each direct category root has a `train_test_split.json` with `train` and `test` arrays
3. **DOF invariant**: All 8 source categories have `joint_2` as DOF index 1 — verified by the generation script before modification
4. **Isaac Gym loading**: The modified URDF loads without errors (test via `UnidoorManipEnv(task_name='leverdoor_direct_pull', ...)`)
5. **Handle immobility**: During an episode, `door_handle_dof_tensor[:, 0]` stays at 0.0 throughout
6. **Expert collection**: `bash scripts/gen_demonstration_unidoormanip.sh leverdoor_direct_pull` produces zarr episodes where door opens beyond 30° without handle rotation
7. **Regression**: `bash scripts/gen_demonstration_unidoormanip.sh leverdoor_ccw_pull` still works — handle rotates then door pulls open
